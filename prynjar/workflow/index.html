PRynjar / Walkthrough

A review, from
the keyboard.

Open a change, find what matters, and keep reading. These are photographs of the working product reviewing its own repository.

Linux · true 2× captures · 26 September 2026. Every caption names the build and the change under review. On a small screen, scroll within an image or open it at full size.

OpenReadMoveFindDraftScale

01 / Start with a repository

Your working tree is a review, too.

Open a folder from disk with Shift + G, compare two refs, or review uncommitted work. A pull request is optional.

Each repository gets its own window. The repositories view brings you back to work this machine already knows.

See the repositories view
See the changed-file list

02 / Read the code

The diff, with its context.

Syntax colour, both line-number columns, and per-file additions and deletions. Press M for side by side, or O for the whole file at the change.

The whole-file gutter marks changed regions even when they are off screen.

03 / Find your pace

Reading has a walking speed.

W and S read onward in the default FPS layout. Fresh taps close together add speed; holding a key keeps the current pace. Pause, then press again to start at a walk.

The reading-speed panel adjusts the walking distance, acceleration and time between taps. ? opens the full key map.

04 / Ask a smaller question

Search the change.
Follow a line back.

Search file names, diff text, or the repository at head, with literal and regular-expression modes.

Blame looks at the base: who last touched this line before the change? For a new line, there may be nothing to blame.

05 / Say what you found

Write now.
Submit deliberately.

Anchor a draft to a selection on either side of the diff. Drafts stay in the local store and survive restarts; moved code is handled explicitly when the change updates.

With a hosted review, submission is a separate batch. In a local review there is nowhere to send it, and the interface says “no remote”.
